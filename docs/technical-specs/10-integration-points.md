# 10. Integration Points

| System                       | Contract                                                                                                                                                          | Failure mode                                | Fallback                                                                                                                                                        |
| ---------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| PostgreSQL                   | Drizzle ORM, parameterized queries only                                                                                                                           | Connection refused/timeout                  | None; the application cannot serve any data-backed route without it. The health endpoint (Section 5.7) surfaces this as `database.status != "ok"`.              |
| Redis                        | `ioredis` client, used by `src/lib/rate-limit.ts`                                                                                                                 | Connection refused                          | Required in production (boot-time failure via `src/lib/env.ts`); in development, the rate limiter logs a warning once and no-ops rather than blocking requests. |
| Google OAuth                 | better-auth's OAuth provider config                                                                                                                               | Provider unreachable or credentials invalid | User falls back to email/password login; Google sign-in button is only rendered when both `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET` are present.            |
| GitHub / LinkedIn OAuth      | Same shape as Google, planned                                                                                                                                     | N/A yet                                     | Not yet implemented                                                                                                                                             |
| Email (Resend or nodemailer) | `src/lib/auth/index.ts`'s `EmailService`, picks a provider based on which environment variables are configured (`RESEND_API_KEY` versus `EMAIL_HOST` and related) | Send failure                                | Logged via `src/lib/logger.ts`; no retry queue exists. A failed verification or password-reset email requires the user to request a new one.                    |

No cache-invalidation rules apply beyond the rate limiter's own TTL-based windows (Section 7.3); there is no read-through or write-through cache for application data today.
